<summary>
- The pi backend gains its session implementation: one conversation per session id, running over the pi runner the project already has.
- Opening a session by id produces a runner pinned to that id and configured to keep its transcript, so a second prompt on the same id continues the first.
- A caller with no session identity gets exactly the runner it had before — nothing about the existing task-routed path changes.
- Closing a session is a no-op, because a pi session holds nothing between turns: each turn is its own process, and continuity lives in the pi CLI's own session store.
- A failed turn surfaces as an error the service already knows how to report; a successful one yields the runner's answer as plain text.
- The pi runner's own interface is untouched — this is an adapter over it, not a change to it.
- No new pi mechanism and no new configuration field: continuity keeps using the flags and the config pair that already exist.
</summary>

## 1. The pi session — new file `pi/session.go`

Create `pi/session.go` with the license header used by every other file in the package, `package pi`, and the two constructors below. `session` and `sessionFactory` are the only new types.

### 1a. One conversation over one runner

```go
// NewSession wraps runner as a session: one conversation whose turns are runs.
//
// A pi session holds nothing between turns — each turn spawns its own process, and
// continuity lives in the pi CLI's own session store, keyed by the --session-id the
// runner was configured with. The session therefore adds no state of its own; it is
// the adapter that lets a Runner be addressed the way the shared interactive service
// addresses a conversation.
func NewSession(runner Runner) agentlib.Session {
	return &session{runner: runner}
}

type session struct {
	runner Runner
}

// Prompt runs one turn through the runner and returns that turn's answer as plain
// text.
func (s *session) Prompt(ctx context.Context, prompt string) (string, error) {
	result, err := s.runner.Run(ctx, prompt)
	if err != nil {
		return "", errors.Wrap(ctx, err, "run prompt")
	}
	return result.GetResult(), nil
}

// Close releases the session. There is nothing to release: pi spawns one process per
// turn and exits it before Run returns, so no resource outlives a turn. The method
// exists because the session interface requires it and a backend that holds a
// process needs it.
func (s *session) Close(_ context.Context) error {
	return nil
}
```

Notes that are part of the contract:

- `Close`'s context parameter is `_` on purpose — the method ignores it, and an unused named parameter is flagged by `unparam`. It still satisfies `Session.Close(ctx context.Context) error`. The same `_`-for-unused convention is used in `agent-pi`'s `application.Run`.
- The error is wrapped with `github.com/bborbe/errors`, never returned bare and never built with `fmt.Errorf`.
- Do NOT add a compile-time interface assertion (`var _ agentlib.Session = ...`) — the test in requirement 3 assigns the factory's result to an `agentlib.Session` variable, which proves satisfaction without a package-level declaration.
- No counterfeiter directive: `session` is private and is constructed only through the factory.

### 1b. The session factory over `PiRunnerConfig`

```go
// NewSessionFactory returns a SessionFactory that builds one pi-backed session per
// session id.
//
// base carries the agent's own configuration — AgentDir, AllowedTools, Model, Env —
// and is copied, never mutated. newRunner constructs each session's runner from the
// config this factory derives: pass NewRunner in production; a test passes a recorder
// so it can observe the config each path produces.
//
// The derived config is base with the continuity pair set from id. A non-empty id
// turns persistence on and pins the run to it, which is what makes a second prompt on
// the same id continue the first. An empty id leaves both unset, so a caller with no
// session identity keeps exactly the runner it had before — the task-routed shape,
// unchanged.
func NewSessionFactory(
	base PiRunnerConfig,
	newRunner func(PiRunnerConfig) Runner,
) agentlib.SessionFactory {
	return &sessionFactory{base: base, newRunner: newRunner}
}

type sessionFactory struct {
	base      PiRunnerConfig
	newRunner func(PiRunnerConfig) Runner
}

func (f *sessionFactory) Create(id string) agentlib.Session {
	config := f.base
	config.PersistSession = id != ""
	config.SessionID = id
	return NewSession(f.newRunner(config))
}
```

Notes that are part of the contract:

- `config := f.base` copies the struct, so `Create` never mutates the factory's own config and two sessions never share one. `PersistSession` and `SessionID` are the only two fields the factory sets; every other field of `base` must survive untouched (the test asserts this).
- `PersistSession` and `SessionID` already exist on `PiRunnerConfig` — this prompt reads and sets them, it never declares them. Do not touch `pi/pi-runner-config.go` at all.
- The `newRunner func(PiRunnerConfig) Runner` parameter is the seam that makes the derived config observable. `pi.NewRunner` has exactly that signature, so a production caller passes it directly; a test passes a closure that records the config and returns a `mocks.PiRunner`.
- `Create` is construction only — no I/O, no logging, no error path. It cannot fail, which is what `SessionFactory.Create(id string) Session` requires.

Imports for `pi/session.go`: `context`, `agentlib "github.com/bborbe/agent"`, `github.com/bborbe/errors`.
